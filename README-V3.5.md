# PersonalCRM Ver.3.5 — Web注文条件テンプレート・納品検収

## 追加機能

見積詳細の注文書作成欄で「Webサイト構築（標準）」を選び、「選んだテンプレートを反映」を押すと、以下を入力します。反映後は案件に合わせて自由に編集できます。

- 公開前・公開後の確認、顧客への確認依頼受領後7営業日以内の結果連絡、修正・再確認、顧客の明示的な承認による検収完了。
- 確認端末・ブラウザ。
- 合意内容との相違と、追加変更依頼の扱い。
- 検収後の不具合と、保守・運用の扱い。
- SEO設定等の確認と、順位・問い合わせ件数等の成果保証の範囲。
- 公開前6件・公開後5件・引継ぎ4件、合計15件の納品・検収確認項目。

「7営業日」等は標準案です。営業日の取り扱い、対象端末・OS、業務範囲、検収後の対応内容などを案件に合わせて確認してください。期間経過だけでは自動的に検収完了にしません。

## 更新手順

1. 既存コード・Supabaseデータをバックアップ。
2. **018適用済みの場合は `supabase/migrations/019_order_templates_and_acceptance.sql` のみを1回実行。018を再実行しないでください。** 未適用なら、従来の導入手順に従い018→019の順で適用します。
3. 今回のコードを既存リポジトリへ反映。既存の.env.localとVercel環境変数は保持。
4. package.json / pnpm-lock.yaml / package-lock.jsonも更新版を反映。依存バージョンは前回のpnpm修正版を維持しており、新しいライブラリ追加はありません。
5. `pnpm install --frozen-lockfile` → `pnpm test` → `pnpm run build`。本番は `NEXT_PUBLIC_DEMO_MODE=false` でデプロイ。

MFや締結ぱっとの追加設定は不要です。本番へのSQL適用・デプロイ・外部サービスへの送付は、この配布時点では実施していません。

## 注文書作成

1. 送付済みの有効な見積を開く。
2. 「注文書・電子サインへ」→テンプレート「Webサイト構築（標準）」→「反映」。
3. 納期・納品場所・支払条件を入力し、テンプレートの検収条件・追加変更・保守等の文章と確認環境を編集。
4. チェック項目の段階・文章を編集。不要な項目は削除し、独自の確認項目は追加できます。自由入力でも確認項目を最低1件登録します。
5. 確認チェックを付けて注文書を作成。条件・別紙項目はこの時点で固定されます。テンプレートを再反映すると入力中の条件・項目を置換するため、確認ダイアログを出します。納期・納品場所・支払条件は再反映でも保持します。
6. 注文書 / PDFには、追加条件と別紙「納品・検収確認項目」を含めて出力します。**締結ぱっとには別紙を含む全ページをアップロード**し、署名欄の位置を確認してください。

注文書を作成した後の文言修正は、既存の固定ルールどおり、未署名なら取消→見積コピー→新規注文書で対応します。署名済みの注文内容を上書きしません。変更には別途の合意を残してください。

## 納品・検収の記録

1. 受注確定後、注文詳細の「納品・検収」→「チェック結果の記録を開始」。
2. 注文時の別紙項目について「未確認／確認済み／要修正／対象外」とメモを記録し、途中保存します。対象外とする場合は理由を記載します。メモはPDFにも掲載されるため、顧客に共有できる内容とします。認証情報・パスワードは記載しません。
3. 顧客への確認依頼日、本番公開日、顧客の承認者、承認内容・方法・日時（メール/LINE内容や検収書管理番号等）を記録。
4. 未確認・要修正を解消し、対象外には理由を記載した上で、顧客の明示的な承認を確認して「検収完了」。検収完了日は注文書締結日以降、確認依頼日・本番公開日以降で、未来日ではない日付を指定します。
5. 検収完了の記録は上書きできません。画面を複数開いていた場合は古い画面からの保存を拒否し、上書きを防ぎます。

注文書への署名（発注承認）と、納品後の検収承認は別の記録です。チェックの「確認済み」だけで、顧客が承認したとは扱いません。顧客本人の入力・電子署名を自動取得する機能ではなく、種村さんが承認の証跡を確認して登録します。必要であればチェックリストPDFを締結ぱっとへ渡して検収書として署名を依頼し、その管理番号等を承認記録に残せます。

検収完了によってMFの請求書や入金を自動更新しません。前受け、分割請求、検収後請求など、契約の支払条件に従い従来の請求予定から操作してください。

## 印刷・PDF

- 注文書 / PDF：条件と注文時の別紙項目を固定表示。チェック結果が後日更新されても注文書PDFの別紙は変わりません。
- 納品・検収チェックリスト / PDF：現在の確認結果、メモ、日付、承認記録を出力。開始前は未記入の確認票として出力できます。
- A4、倍率100%、ブラウザのヘッダー/フッターOFFを推奨。チェック項目数や文章量でページ数が変わるため、送付前に全ページを確認してください。
- 汎用の記入用Markdownも `docs/web-delivery-checklist.md` に同梱しています。

## 既存注文書

019で既存の注文条件は変わりません。作成時の別紙がない旧注文では、受注確定後に標準15項目を**運用記録として**追加できます。署名済み条件を変更しないことを確認して開始し、契約対象外の項目は理由を記録してください。

## 保存・権限

- 注文時の条件と別紙：sales_ordersの追加列に保存。
- 作業結果と承認記録：本人専用のorder_acceptancesに保存。直接更新を許可せず、所有者・改訂番号・検収完了条件をDB関数でも検証します。
- 既存の全データJSONバックアップにorder_acceptancesを追加。署名済みPDF本体の扱いは従来どおり別途バックアップです。
